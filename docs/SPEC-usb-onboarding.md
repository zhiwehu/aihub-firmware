# USB 一体化接入

用户授权：电脑通过 USB 给兼容 EchoEar 写入 Wi-Fi 和当前 VoiceHub 连接信息，自动准备设备监听，随后检查上线与语音；模型页移除重复 MCP 配置。

模块与顺序：MCP 配置归位 → 管理端自动准备设备监听 → 浏览器 NVS 保留式修改 → USB 备份/写入/读回/重启 → 上线与语音验证。

## 接口与行为

- POST /api/clients/echoear-s3/prepare，JSON {} 或 {host:本机网卡地址}；复用管理员认证和同源检查，选择当前物理局域网网卡并幂等启动设备专用监听。多个无法确定的网卡返回可选择网卡；不开放管理台，不替换正在工作的其他监听。
- 返回当前设备 OTA/WebSocket 配置，no-store；Wi-Fi 密码不发到后端、不存浏览器持久存储、不写日志。
- 用户 USB 识别通过后填写 SSID/密码，点击保存设置备份并连接。**备份范围与即将写入的范围一致**：只配网时保存并重新读取校验设置备份（分区表、启动记录、NVS，约 28 KB）；勾选同时更新固件时，先保存并校验整机备份（上述三项 + 两个应用分区，约 8.1 MB）。两份备份都必须完成磁盘写入、回读和浏览器校验后才允许写设备。
- 整机备份只包含本工具可能覆盖的区域。引导程序、分区表和资源区从不写入，因此不复制；旧版 16/32 MB 完整镜像备份保持可读可恢复。
- 写入只发生于 NVS 与（升级时的）目标应用分区和启动记录；不写引导程序、分区表、资源区，不跨设备恢复，不自动刷写未经实机验收的新应用。
- 支持已通过现有芯片、安全配置、精确分区校验的设备。损坏/加密/未知 NVS、空间不足和受保护设备明确失败，不清空设备设置。应用镜像或启动记录损坏时仍允许配网，并明确提示不能升级。
- 读取按 64 KB 分块，优先 4 KB 数据帧，连接时以一次 64 KB 读取探测，失败则重连并回落到 1 KB 帧；每条命令的设备侧 MD5 摘要必须通过。断线重连后必须核对 MAC、容量、分区，并对已读区域重新取设备摘要比对，发现设备变化即停止。
- 写入后用设备端 MD5 摘要校验写入区域，缺省才回退为整段回读比对。
- 浏览器记住已授权的串口并在下次直接复用；设备已保存 Wi-Fi 时提供一键配网，不再要求填写表单。
- 选取浏览器本机 VoiceHub 使用；远端电脑托管和 AP 客户端隔离需明确说明，不能把写入成功等同设备已上线。
- MCP 城市/新闻源/数量放在工具卡，规划器/超时放在 MCP 页面全局设置。模型页 GET/PUT /api/config/models 仅操作模型、音频、唤醒、提示词及记录保留；不读取或提交 MCP 字段。MCP 使用 /api/config/tools，按工具卡保存设置。

## 备份容器

版本 2：`VOICEHUB-DEVICE/2\n` + JSON 长度 + 元数据（version、kind=settings|full、mac、layout、flashSize、firmware、regions[{name,address,size,sha256}]）+ 各区域原始字节。区域名与地址固定为 table 0x8000/4 KB、otadata 0xd000/8 KB、nvs 0x9000/16 KB、app0 0x20000/0x3f0000、app1 0x410000/0x3f0000；settings 必须且只能包含前三项，full 必须包含全部五项。服务端独立校验结构、长度和每个区域的 SHA256。

版本 1（16/32 MB 整片镜像）继续接受并解码为同样的区域视图。

## 验证

Python unittest 覆盖管理员/跨域、网卡选择、端口冲突、监听幂等、设备 OTA 鉴权，以及 v2 容器的区域集合、长度、摘要与身份校验。
Node 覆盖 NVS CRC/字符串/多页/无空间、非目标原始记录保留、MAC/快照变化拦截、只写 NVS、读回失败、备份恢复、两种备份级别、区域复用、4 KB 帧探测与 1 KB 回落、可变帧长与摘要失败。
生成合成 NVS，使用本机 ESP-IDF 官方工具独立校验修改后分区。浏览器检查流程、模型页与 MCP 页以及窄屏布局。实机写入由用户点击连接完成，记录上线与播放证据。

命令：在本仓库运行 python3 tests/test_firmware_logic.py；node --test tests/*.mjs；node --check flash/echoear-installer.js。
沿用 Python/aiohttp 和原生 JS，不增加依赖。数据备份不提交仓库，文档不得包含用户凭据。
