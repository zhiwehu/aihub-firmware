# USB 一体化接入

在运行 VoiceHub 的电脑上，用 Chrome / Edge 打开 http://127.0.0.1:8765/#connections 。准备兼容 EchoEar 猫头、电脑和 USB 数据线即可。

## 1 → 2 → 3

1. **连接设备**：插上猫头 USB，点“开始连接”。第一次需要在浏览器弹窗里选一次喵伴，之后同一浏览器会自动复用这个串口，不再弹窗。检查芯片、分区与启动记录约 1–2 秒。
2. **配网**：喵伴保存过 Wi-Fi 时，页面直接给出“一键配网（沿用已保存的 Wi-Fi）”，点一下即可；需要换网络时点“换一个 Wi-Fi”填写名称和密码，开放网络需明确勾选。
3. **开始对话**：设置写入并读回核对后自动重启，等待上线，唤醒并说“你好”，听到回复后点确认。

**“沿用 Wi-Fi”使用的是喵伴中已保存的凭据，不是读取电脑密码。** 浏览器不提供直接获取电脑已保存 Wi-Fi 密码的接口；本产品不调用系统钥匙串或额外索取电脑密码。若喵伴没有已保存网络，页面会要求填写，并保留 USB 连接供重试。

新填写的网络名称和密码仅通过本机 USB 写入。备份仅发送到本机回环地址的 VoiceHub 服务，保存于数据目录下 `device-backups/<设备MAC>/`，不发送外部服务，不存入浏览器持久存储。目录权限为0700、文件0600；每次保留独立副本，不覆盖旧备份。磁盘写入、同步、回读和浏览器校验成功后才允许写设备。

## 备份分两级

写入范围决定备份范围，不再为一次改设置读取整片 Flash。

| 级别 | 何时生成 | 内容 | 大小 | 恢复范围 |
|---|---|---|---|---|
| 设置备份 | 每次配网（默认） | 分区表、启动记录、NVS | 约 28 KB | 只写回 NVS |
| 整机备份 | 勾选“同时更新固件”或点“立即备份” | 上面三项 + 两个应用分区 | 约 8.1 MB | 两个应用分区、NVS、启动记录 |

本工具只会写这些区域：应用分区、NVS、启动记录。引导程序、分区表和资源区（assets）从不写入，未分配空间与它们无需复制，因此整机备份是 8.1 MB 而不是 32 MB 的整片镜像。旧版本保存的 16/32 MB 完整镜像备份仍然可读、可恢复。

完整备份读取时每 64 KB 发一条命令；同一设备再次备份时，应用分区先由设备计算 MD5 与旧副本比较，一致就复用，不一致才重读。设置区每次重读，不做缓存。

## 自动准备与读取

设备专用监听与 OTA URL 自动配置，不需要填写 IP、端口或令牌。虚拟 feth、VPN 等接口不作为配网候选；macOS 用系统硬件端口标识真实 Wi-Fi。电脑换网络后，未被在线设备使用的旧监听自动迁移；有设备在使用时保持原连接并明确提示。

读取优先用 4 KB 数据帧（与 Espressif 官方浏览器实现相同），连接时先用一次 64 KB 读取探测；探测失败会断开重连并回落到 1 KB 帧，再失败才降速重试。每条命令结束时由设备返回 16 字节 MD5 摘要，浏览器逐条核对，帧长不符或摘要不符都算失败，不会把坏数据当成固件。

读到一半断线会自动重连，按失败块重试；重连后必须核对 MAC、容量、分区，并对已读区域重新取设备摘要比对，发现设备被重新刷写或重新配网就停止，不拼接混合快照。

同一浏览器同源接入页通过 Web Locks 协调 USB 归属，直到断开或页面关闭后释放。不要同时在其他浏览器、串口工具或旧版页面操作同一个 USB；这些程序不受该页面锁管理。

## 高级选项

升级、恢复、手动热点配网及设备服务设置均收在“高级选项”。已有兼容固件无需升级。只有通过实机验收的适配版本才能勾选同流程更新，候选版本不会因配网而开放安装。

“立即备份”保存整机备份。“恢复最近可用备份”自动查找本机保存的最近副本，匹配设备 MAC、分区和容量；损坏文件或启动镜像校验不通过时继续查找更早的副本，无可用副本则停止，用户无需选择文件。恢复整机备份会写回两个应用分区和设置；只做过配网备份的设备只写回设置，固件不动，页面会明确说明。旧版手动另存的文件保留在原目录，不会自动扫描或导入。

NVS 追加空间不足时，会在内存中整理已失效的旧记录，完整保留有效记录、未知二进制数据和命名空间索引，并逐项比对；仍保留一页供设备垃圾回收。只有有效配置本身已满、损坏 NVS、设备保护或适配校验未通过时停止，不清空设置。设置写入成功与实际上线分别检查；同名 Wi-Fi 也可能隔离客户端，设备未上线时需核对网络可达性。

应用损坏或启动记录异常时仍可配网：配网只需要分区表、MAC 与 NVS，不需要读应用镜像。这类设备会在连接时提示“只能配网，不能升级”。

## 配置页面

“模型与语音”只保存模型、音频、唤醒、提示词和记录保留，不读取或提交 MCP 设置。工具参数位于各 MCP 卡片的“配置与测试”；规划方式与通用超时位于 MCP 页。

本轮自动化、独立校验与实机验证记录见 `docs/VALIDATION-usb-onboarding.md`。

自动备份接口仅限本机回环访问：`POST /api/clients/echoear-s3/backups` 接受有界备份，返回不可变ID；`GET .../backups/{id}` 回读指定副本；`GET .../backups/latest?mac=...&layout=...&flashSize=...` 查找匹配设备的最新完整性有效副本，可用 `before` 继续向前查找。应用和启动记录的语义校验仍由浏览器完成后才允许恢复。

## 提速做了什么

| 改动 | 效果 |
|---|---|
| 配网只备份并写入设置区 | 首次配网从读 32 MB 变成读 28 KB，秒级完成 |
| 整机备份只读可写区域 | 32 MB → 8.1 MB |
| 4 KB 数据帧，失败回落 1 KB | 同样的字节数约 4 倍少往返 |
| 写入校验改用设备端 MD5 | 每次写后不再整段回读 3–4 MB |
| 连接时不再读整份应用镜像 | 第一步检查从十几秒降到 1–2 秒 |
| 记住串口 + 一键配网 | 少两次点击和一次表单提交 |

实测基线：实机 32 MB 完整读取 288.7 秒（1 KB 帧，1 包在途）。新流程下的实测数据需在实机上重新记录。
